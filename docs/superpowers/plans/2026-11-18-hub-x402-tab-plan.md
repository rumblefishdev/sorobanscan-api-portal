# The Hub's x402 Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A member signed in to the hub sees an x402 tab with their key's state, "Get API Key", Show and Copy, and Regenerate, served by the BFF calling x402's backend with tokens of x402's own.

**Architecture:** The BFF's token signer and product client take the product's name instead of having Prices' written in; settings gain x402's secret name and API; the page gains `src/account/x402/` built from the Prices tab's parts. Both sides are opt-in (`HUB_PRODUCTS`, `VITE_PRODUCTS`), so production stays on Prices alone.

**Tech Stack:** Node 22, TypeScript, Hono (BFF), React 19, MUI on the account pages, Vite 8, Vitest; `corepack pnpm`.

**Spec:** `docs/superpowers/specs/2026-11-17-shared-sign-in-design.md`, "x402 joins" (decisions 17-25), with decisions 12, 15 and "The dashboard contract". The backend's half: `docs/superpowers/plans/2026-11-18-x402-hub-contract-plan.md` (its Task 5 has the contract's exact answers).

## Review Focus

1. `HUB_PRODUCTS=prices,x402` with x402's secret unreadable (no AWS grant yet): x402's calls answer `503 product_not_configured`, and the Prices tab keeps working. (Task 3)
2. A token for one product must never reach the other: with both on, every request to x402's API carries `aud: "x402"` under x402's secret and context, and every request to Prices' carries Prices'. (Task 3)
3. x402's backend down or answering a Cloudflare challenge page (HTML, 403 or 200): the tab shows "x402 is unavailable", never "sign in again" and never a blank card. (Tasks 2, 4)
4. An active key x402 can't show (`details.showable: false`, or `409 key_not_viewable` on a race): no Show or Copy offered; a pressed one says the key can't be shown and that Regenerate ends it. (Task 4)
5. `?issue=capped` and `?issue=too_young` on the x402 tab: the outcome is said in words with the date from `account`, read once and taken off the address, as on the Prices tab. (Task 4)

```ts
export type X402Key =
  | { state: "none"; can_issue: boolean }
  | { state: "active"; key_id: string; created_at?: string | null; can_issue: boolean }
  | { state: "revoked"; revoked_at?: string | null; next_eligible_at?: string | null; can_issue: boolean };
export interface X402Account { key: X402Key; showable: boolean }   // details.showable; false when absent
export function fetchAccount(signal?: AbortSignal): Promise<X402Account>;
export function revealKey(): Promise<{ key_id: string; value: string }>;
export function revokeKey(): Promise<{ revoked_at?: string; next_eligible_at?: string }>;
```

**What the tab shows** (the Prices tab's layout and theme, without its usage and rate-limit panels):
- No key, or revoked with `can_issue: true`: "Get API Key" (the form `POST`).
- Active: the key masked, its id and issue date; Show key and Copy key (absent when `showable` is false, with the line "This key can't be shown again. Regenerate ends it; a new key can be issued from the next calendar month."); Regenerate, behind the same dialog and typed phrase as Prices', which revokes and issues nothing.
- Revoked with `can_issue: false`: "Your key was revoked on <date>. A new key can be issued from <next_eligible_at's date>."
- Under an active key, the rule as Prices states its own: "Regenerating is limited to **once per calendar month** and issues nothing now."
- Two tiles: "Mainnet (pubnet)" / "API key required on /verify and /settle", and "Testnet" / "No API key needed".
- `?issue=`: `issued`, `has_key`, `capped`, `too_young`, `failed` and the gates' reasons in the words the Prices tab uses, with "x402" where it says "Prices".
- Failures: `x402_unavailable` and `x402_busy` → "x402 is unavailable right now. Try again in a moment."; `product_not_configured` → the same line; `401` → the session ended, to `/login`.
